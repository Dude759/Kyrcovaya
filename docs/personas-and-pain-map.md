# Персоны и карта боли

Версия 1.0, 6 октября 2026 года. Персоны — вымышленные проектные гипотезы, созданные для проверки сценариев. Интервью и наблюдение за реальными водителями/операторами ещё не проводились. Имена, возраст, расписание и оценки не являются результатами исследования.

## Персона 1: водитель

**Алексей, 29 лет.** Пользуется электромобилем для городских поездок. Обычно открывает сервис на телефоне, заряжается между рабочими делами. Его главная задача: выбрать совместимый свободный порт на подходящее время и понять ожидаемую стоимость до подтверждения.

| Характеристика | Проектная гипотеза |
| --- | --- |
| Контекст | Ограничен по времени, не хочет ехать к занятой или неисправной станции |
| Информация для решения | Разъём, мощность, адрес, свежесть статуса, тариф, свободный интервал |
| Ограничения | Небольшой экран, нестабильная связь; модель автомобиля не гарантирует наличие переходника |
| Критерий успеха | Подтверждена одна бронь, виден результат оплаты, начатая зарядка и итоговая история |
| Риск доверия | Красивый «свободна» без даты измерения или сообщение об оплате без подтверждения сервера |

## Персона 2: оператор

**Сергей, 35 лет.** Сотрудник организации, обслуживающей несколько ЭЗС. Получает аккаунт от администратора. Работает преимущественно за компьютером, одновременно наблюдает несколько объектов. Его задача: обнаружить проблему, понять её влияние и применить контролируемое изменение.

| Характеристика | Проектная гипотеза |
| --- | --- |
| Контекст | Следит за сетью, а не за одним автомобилем; реагирует на дефицит и потерю связи |
| Информация для решения | Активные сессии, измеренная нагрузка, доступный бюджет, статус команды, свежесть и источник прогноза |
| Ограничения | Может управлять только своей организацией; нельзя останавливать/обслуживать объект без проверки активных процессов |
| Критерий успеха | Проблемный объект найден, изменение подтверждено устройством/имитатором и записано в журнале |
| Риск доверия | Расчётная мощность выдана за измеренную, старая телеметрия за свежую, ML-прогноз за гарантированный бюджет |

## Как проверить гипотезы

В следующем пользовательском исследовании предлагаем две короткие задачи водителю: найти CCS2 ≥ 100 кВт на выбранный интервал и восстановиться после отказа тестовой оплаты. Оператору: найти объект с устаревшей телеметрией и объяснить, почему при бюджете 150 кВт четыре запроса получили по 37,5 кВт.

Фиксируем время, успешность без подсказки, ошибки, число обращений за помощью и понимание статуса/источника данных. Для водителя используем существующий ориентир UX — не более 3 минут и 5 смысловых шагов до подтверждения; это целевые значения, не измеренные результаты. Протокол указывает участника обезличенным кодом, версию приложения и сценарий. Ответы и замечания добавляются только после реального проведения, с согласия участника.

Результаты анализа интерфейса можно использовать для уточнения гипотез, но нельзя называть пользовательским интервью. Источники для отраслевых наблюдений приведены в [анализе аналогов](analog-analysis.md); требуемое поведение — в [ТЗ](system-requirements.md), сценарии — в [Use-case](use-cases.md).
