## Признаки и доступность

| Признак | Доступность на origin | Правило |
|---|---|---|
| Час/day-of-week target, выходной, циклический календарь | Известны заранее | UTC; региональный календарь только зафиксированной версии |
| h=1..24 | Известен при запросе | Multi-horizon row, общий origin |
| load лаги 1/24/48/168h | Только complete и available_at<=origin | Лаг определён относительно origin, не target; иначе может попасть в будущее |
| Среднее/std/min/max по прошлым 24/168h | Только известное прошлое | Счётчик пригодных точек/age; partial не заменять нулём |
| Latest known load и age | available_at<=origin | Отсутствие → missing indicator, не искусственный target |
| Quality/coverage/age | Только фактически доступные записи | Не подставлять будущую quality целевого часа |
| Известные локальные/Grid лимиты | Получены и действовали до origin | Не использовать будущий сценарий или последнюю конфигурацию для старой даты |
| Брони и активные сессии | created_at<=origin и историческое состояние известно | Не использовать фактическую будущую длительность/исход; без as-of state исключить |

Snapshot 6A не содержит полной версии исторических бронирований/состояний на каждый
origin. Эти признаки пока исключены. `snapshot_limit_kw` — текущая конфигурация,
не исторический feature; future synthetic budget/counts/demand не использовать.
Local limit из derived таблицы тоже требует доказательства as-of происхождения:
исторический fallback существующего агрегатора может использовать конфигурацию.

## Следующий инкремент

1. Зафиксировать pinned Python/scikit-learn/numpy, feature schema и версию данных.
   Делать трансформации внутри временного train; imputer/selection fit только train.
2. Обучить RF, выбрать ограниченную сетку параметров по validation и одинаковым
   общим origin/h с baseline. Test запрещён для выбора признаков/параметров.
3. Зафиксировать выбранную конфигурацию до однократной оценки test. Сохранить MAE/
   RMSE по h и общий пул, n, coverage. Не обещать превосходства baseline.
4. Сохранить model artifact, training manifest/hash, feature schema, версии и метрики.
   Проверить загрузку артефакта и replay прогнозов после рестарта Python.
5. Ввести защищённый API 24h forecast с source, modelVersion, origin, asOf,
   training range, quality, nullable points и expiry. Нет истории → no forecast.
6. Периодическое обновление без обязательного платного постоянно работающего сервиса;
   идемпотентный job, контроль возраста и изоляция организации.
7. Операторский UI: actual / forecast / baseline отдельно, synthetic явно помечен.
   Прогноз только информирует; Grid/device safety и dispatch от ML не зависят.
8. Сравнить на новой реальной истории и проверить domain shift. Синтетические метрики
   не доказывают качество на настоящем оборудовании или качество управления сетью.
