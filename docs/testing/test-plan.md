# Тест-план платформы

Версия 1.1, 26 октября 2026 года. Stage 2A выполнен: [фактический backend-протокол](backend-results.md). Проверки будущих серверных процессов I01–I12 и ML пока **NOT RUN**. Предыдущие проверки клиентского mock описаны в [frontend QA](../frontend-qa.md); они не заменяют проверки сервера.

## Среда и протокол

Для серверных проверок используем отдельную тестовую PostgreSQL с миграциями текущей версии. Сетевой и платёжный адаптеры — управляемые имитаторы с явным происхождением данных. В тестовой БД нужны две организации, по одному оператору каждой и два водителя: основной демонстрационный seed с одной организацией сам по себе не проверяет изоляцию организаций. Очистка допустима только для специально выделенной тестовой БД.

Каждый прогон записывает дату, commit, версии среды, набор данных, точную команду, ожидаемый/фактический результат, статус PASS/FAIL/BLOCKED и ссылку на очищенные от секретов логи. NOT RUN означает отсутствие прогона. Один тест может проверять несколько требований, но его результат не переносится на весь этап автоматически.

## Общая интеграция и приёмка

Проверяем полный сценарий двумя независимыми браузерными контекстами: водитель выполняет действия, оператор наблюдает те же серверные данные. Приёмка включает клавиатуру, ширину от 320 px, повтор после сетевого отказа и явную маркировку имитаторов. В HTTP-режиме запрещён незаметный успех через локальные моки.

Для целевого стенда 6–20 станций, до 200 портов и 50 пользователей измеряем p95 обычных чтений API; ориентир ≤ 1 с из [ТЗ](../system-requirements.md). Протокол указывает длительность, профиль запросов, долю ошибок и характеристики машины. Время внешних карт и платёжных страниц учитывается отдельно. Это запланированное измерение, не текущий результат.

Пользовательские задания и гипотезы описаны в [персонах](../personas-and-pain-map.md). Их протоколы не подменяются автоматическими тестами. Условия завершения Stage 2A — в [общем плане](../coursework-plan.md).
