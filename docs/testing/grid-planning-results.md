GridAdapter: availablePowerKw/baseLoadKw/status/receivedAt/source=simulator.
Настройки — только оператор своей организации через строгий POST с Idempotency-Key.
Сценарии: normal/recovery 500−100=400 кВт; deficit 250−100=150; deep_deficit
120−100=20; offline/stale/missing не дают известного бюджета. Операторский лимит
берётся из конфигурации организации, POST не принимает произвольные показания/лимит.
GRID_FRESHNESS_SECONDS конфигурируется (5–3600, default 60), включительная граница.
В расчётах целые Вт: max(0,min(operatorLimit,available−base)). Невалидное/будущее
время, отрицательные/нецелые Вт и отсутствие данных не дают положительного бюджета.

max-min-integer-v1: прогрессивно одинаковое увеличение до насыщения запроса, порта,
станции или бюджета; свободная мощность перераспределяется. Остаток в 1 Вт выдаётся
по стабильному ID. Вход сортируется независимо от порядка PG. Для 100/80/60/50 кВт
при 150 кВт — 37.5 каждому; при 20 кВт — 5 каждому. Станционные лимиты групповые.
Чистая функция не смешивает организации: каждый серверный запуск ограничен одной.

Live demand — стартовое выделение сессии как явно сохранённый proxy спроса: раньше
отдельный пользовательский power-request не хранился. Физический предел порта и
локальный лимит станции учитываются дополнительно. Training — отдельные явно
учебные запросы, не выдаваемые за физические станции/сессии. UI всегда помечает
«Расчёт, не применяется к зарядкам». Реальная энергокомпания не подключена.

Worker обновляет snapshot/план каждые 15 секунд только настроенных организаций.
Org advisory lock, snapshot и неизменяемые входы/результаты переживают рестарт.
При устаревании GET помечает ранее сохранённый план unusable; UI не показывает его
как текущее назначение. GET read-only, не меняет сессии или устройства.
History limit 1–100, keyset id, строгие параметры и обязательный scope организации.
