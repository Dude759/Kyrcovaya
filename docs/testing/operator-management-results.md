007 добавляет network_events (immutable аудит до/после с actor/org/station/port)
и operator_requests (org/key/hash/result). 001–006 неизменны. Все записи создаются
одной транзакцией с аудитом. Повтор создания возвращает первоначальный ID/ответ;
другой payload с ключом даёт 409. ID teaching-UUID и организация задаются сервером.
Строгий JSON, координаты [longitude,latitude], рублёвый тариф с точностью копейки,
локальные лимиты и физические мощности проверяются до записи.

Станция создаётся service; online разрешён после добавления хотя бы одного idle
порта. Управление блокирует station, затем все ports в порядке UUID; не блокирует
после этого payments, сохраняя порядок с бронированием/зарядкой. Флаги API в SET LOCAL
включают operator_object_guard в этой транзакции. Доверенные SQL измерения/maintenance
могут сообщить физический отказ независимо от пользовательской настройки (это
нужно для сценариев 3D). Прямого клиентского SQL нет; права оператора проверяет API.

Service/offline/archive запрещены при незавершённых сессиях и действующих held/
confirmed резервах с end>PG clock. Уменьшение мощности/лимита ниже суммы выделений
starting/active/stopping запрещено. Максимум станции согласуется с портами. Тип
порта с платёжной историей не меняется. Физическое DELETE запрещено; архив скрыт
из нового каталога и бронирования, но доступен по ID и в истории workspace.
Тарифные снимки не изменяются при редактировании текущего каталога.

HTTP операторский экран использует прежний AppShell/формы/Modal; mock сохранён.
Есть станция, координаты/тариф/лимиты/режим, физические порты, подтверждение архива,
постраничный аудит. Нет обещаний связи или реального оборудования; учебность явная.
Общий GridAdapter/max-min/ML/OCPP/банки/принудительный stop остаются закрыты.

активацию и каталог, конкурирующее идемпотентное создание, scope/инъекцию org,
