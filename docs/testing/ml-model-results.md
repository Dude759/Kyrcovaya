# Stage 6B — RandomForest + исторический Forecast API

Локальная реализация; публичная приёмка PENDING до CI → merge → Render/Pages одного SHA → smoke → браузер. Финальный SHA, ссылки на CI и публичный протокол добавляются в описание release PR после приёмки, без нового deploy только ради статуса документа.

## Эксперимент

Источник synthetic: неизменный генератор Stage 6A, 180 суток / 4320 сетевых часов, 8 станций, seed 20261101. Dataset SHA256 `2f39bfa1271973d03c3231ec148b7c868afa5f94730d8895e654480ddac9583e`.
Фактическая история серверного имитатора NEEDS_MORE_DATA; физическое оборудование не исследовано. Синтетические measurements в рабочие таблицы Neon не загружаются.

Gap 24h; все 24 target часа origin должны входить в один блок. Признаки: 28 столбцов в manifest, единый as-of алгоритм, UTC calendar/horizon, лаги origin−1/24/48/168h, полные доступные прошлые 24/168h, age, missing indicators. Доступность complete: end<=origin и available_at<=origin, с сохранением субсекундной точности. В synthetic quality прошлого известна по завершении часа; для actual ретроспективная quality требует отдельного as-of доказательства. Будущие Grid/counts/брони/длительности исключены. Missing/partial не превращаются в measured zero. Календарные признаки для каждой строки train/inference совпадают.

Train: 58607 строк; median imputer fit только train. Сетка заранее зафиксирована в stage6b-execution-plan.md: (trees/depth/leaf) 32/8/20, 64/10/20, 64/12/10. random_state=20261101, n_jobs=1. Выбор по validation MAE; selection.json записан до вычисления test-метрик. Выбрано 64/10/20. Дальнейшего подбора по test нет. CI --retrain воспроизводит уже зафиксированный опыт, не выбирает новые признаки/параметры. JSON dataset загружается целиком для проверки hash; запрет просмотра test означает запрет использования test в fit/selection, а не отсутствие его байтов в памяти.

Python 3.14.5, scikit-learn 1.9.1, NumPy 2.5.4, SciPy 1.18.1, joblib 1.5.3; полное окружение requirements-model.txt, включая threadpoolctl/narwhals. Модель `rf-synthetic-v1-f0cc10bdc704`, model SHA256 `3b6f608da48b9930abf05561ebd3ddfafc0c95ba981f84d63a4179e941c01bf0`.

## Сохранение и Render

Артефакт: ml/models/rf-v1/{forest.joblib,manifest.json,selection.json,metrics.json,demo-forecast.json}. Доверенный Python loader требует фиксированный repo path, allowlisted modelVersion/model SHA/bundle SHA, dataset hash, порядок признаков и точные версии до joblib.load. Пользовательские pickle/path не принимаются. Проверена загрузка и совпадение прогнозов abs tolerance 1e-8.

**Выбран B: offline historical replay.** Python реально вычислил 24 точки для origin 2026-05-02T00:00:00Z (target end 01:00Z…2026-05-03T00:00Z). GeneratedAt 2026-11-01T20:48:38.976950Z — время обучения, origin не подменяется текущим. Express проверяет allowlisted SHA256 JSON `1427157269dfc2873b6c20ef1b5782924c4c6244501e7394b25e720902ac4ae0`, modelVersion и dataset; Node/DB DTO совпадает с Python bundle вплоть до значений и дат.

Вариант A исследован по официальным [ONNX Runtime Node docs](https://onnxruntime.ai/docs/get-started/with-javascript/node.html) и [sklearn-onnx supported models](https://onnx.ai/sklearn-onnx/supported.html): потребовал бы конвертера всего pipeline, отдельной совместимости версий и parity inference. Конверсия/ONNX parity не испытывались; они не заявляются реализованными. Для данного инкремента B проверен сквозным Python→JSON→PostgreSQL→Node replay без native runtime зависимости. Python в Render Node runtime не предполагается, build/start и ресурсы не изменены.

011 создаёт отдельные immutable forecast_runs/load_predictions; org/FK/unique run+version+origin, 24 последовательных h, source synthetic. Повторный seed идемпотентен. Прогнозы не записываются в readings и не используются Grid/device/settlement. Миграции 001–010 не изменены.

GET /api/operator/forecast: actual, NEEDS_MORE_DATA, forecast=null и причина. GET /api/operator/forecast/demo: только собственный опубликованный synthetic эксперимент, historical=true/staleForCurrentNetwork=true, 24 точки и метрики. Строгий query, 401/403/404, checksum fail→503. POST forecast остаётся 501; вычисления нового origin нет. Workspace.forecast=null сохраняет отсутствие достоверного actual прогноза.

UI отдельно открывает эксперимент по явной кнопке; URL forecast=demo восстанавливает его при reload. Показаны loading/error/insufficient_data, готовый исторический результат и stale-предупреждение, источник/версия/origin/generatedAt, RF/оба baseline, кВт и контекст synthetic test. Baseline null разрывает линию; фиктивной доверительной полосы и процента точности нет. Экспорт — исторические значения. Повторный вход читает тот же immutable серверный результат. Mock сохранён.

## Проверки и воспроизведение

Из ml/, Python 3.14.5:

```sh
python -m pip install --only-binary=:all: -r requirements-model.txt
python -m readiness prepare
python -m model.train verify --retrain
python -m unittest discover -s tests -v
```

Для нового независимого опыта `python -m model.train train --out artifacts/new-experiment`; это создаёт новый generatedAt/bundle checksum, не заменяет доверенный release. Для публикации нового опыта нужны review и обновление allowlist; HTTP не загружает произвольные модели. Не менять frozen split после просмотра test.

Локально: 20 Python-тестов (12 прежних + 8 model), 200 backend (194 прежних + 6 FCT), 93 frontend (90 прежних + 3 HTTP ML). Отдельная PostgreSQL 17 _test, случайные схемы. Полный backend включает долгие simulator/restart/race/rollback проверки старых этапов. FCT проверяют migration/idempotent seed/immutability, authentic Python bundle, реальные dates/units, restart OS process и relogin, отказ роли/организации/неверному входу и отсутствие побочных эффектов. Python проверяет as-of/future perturbation/delay, missing, train-only imputer, frozen support/метрики24h, dependency/schema/provenance и reload parity. Frontend — insufficient→explicit demo, 24 опции, метрики synthetic, URL reload и ошибка доступа.

CI: readiness + model Ubuntu/Windows, установка pinned wheels, повтор frozen обучения, hash/replay/метрики и upload версионированных artifacts. Existing backend/frontend workflows сохраняются. CI и публичная приёмка ещё PENDING до фактических ссылок в release PR.

Локальный браузер: actual без прогноза → explicit historical demo → 24 даты/три линии/метрики; 320px document.scrollWidth=305 при innerWidth=320. Финальный публичный протокол должен отдельно повторить сценарий на опубликованном SHA.

## Ограничения

Synthetic RF выиграл у weekly в этом фиксированном эксперименте; это не доказательство качества реальной сети, экономии энергии или преимуществ dispatch. Нет live inference, новых forecast jobs, confidence interval, weather/booking features, реального оборудования или автоматического ML управления. Actual требует дальнейшего сбора/аудита истории и отдельной временной оценки. Free Render может засыпать; offline результат долговечен в БД и Git. Старые документы/планы нельзя цитировать как описание текущего выпуска без сверки: см. documentation-audit.md.
