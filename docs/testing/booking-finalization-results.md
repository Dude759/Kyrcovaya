## Реализация

- [Миграция 004](../../backend/migrations/004_booking_finalization.sql). Bookings имеют UNIQUE payment/reservation/attempt; составные FK защищают снимок пользователя, организации, станции, порта, типа, интервала, суммы и метода. Обратные ссылки payment/reservation → booking отложены до commit. Constraint triggers не допускают succeeded без той же confirmed booking/reservation и успешной попытки. Снимок подтверждённой брони неизменяем. Файлы 001–003 и payment_order_immutable() не переписаны.
- [finalizePayment](../../backend/src/modules/payments/finalization.ts) — внутренняя операция открытой транзакции. Входом служит проверенный и сохранённый success inbox, а не клиентский параметр. HMAC, timestamp, сумма, валюта и попытка проверяются прежним [signed endpoint](../../backend/src/modules/payments/service.ts). Порядок блокировок: payment → station → physical connector → reservation → attempt/event → compensation. Время clock_timestamp() читается после ожидания блокировок. Вставка booking, confirmed reservation, succeeded payment и результат event коммитятся вместе.
- Повтор event не пропускает незавершённый awaiting_booking/late_success из 3B. Подтверждённый результат идемпотентен; старый истёкший/освобождённый hold не восстанавливается. SQL exclusion остаётся последней защитой порта; конфликт внутри savepoint приводит к компенсации, а не отбору чужого резерва.
- Неудачная финализация сохраняет provider success, finalization_reason и уникальную по attempt компенсацию. Дополнительный success другой попытки уже оплаченного заказа компенсируется отдельно, сохраняя первоначальную бронь.
- Возврат проходит pending → submitted → succeeded. У тестового адаптера отдельная долговечная test_refund_receipts; сумма/ID/время подтверждения связаны FK. Сетевой/процессный сбой до локальной фиксации восстанавливается по прежнему provider_refund_id. До реальной квитанции адаптера возврат не показывается выполненным. Это только симуляция; банковских списаний нет.
- Восстановление запускается при старте и каждые 15 секунд в существующем процессе API, пакет до 20 записей. Нет Redis, отдельного worker/cron или платных ресурсов. Выключенный Free API не обрабатывает очередь до пробуждения; источник истины — PostgreSQL.
- Driver workspace содержит только свои последние 100 payments/bookings, stage=bookings. Бронь показывает UUID физического порта, тип, станцию, время и предварительную сумму. Checkout опрашивает сервер, восстанавливается после reload/login и переводит в список броней. Mock и прежний полный mock-сценарий сохранены. POST /bookings по-прежнему 501; запуск зарядки и отмена confirmed booking не открыты.

## Публичная приёмка и ограничения

После CI → merge → автоматических Render/Pages проверяется совпадение commit. Команда: `node backend/scripts/public-smoke.mjs https://energotransport-api-dude759.onrender.com --reservations --payments`. На публичной Neon только последовательные функциональные учебные запросы: create/replay, fail/retry/cancel, подтверждение одной брони, сохранность после исходного TTL, поздний success отменённого заказа и подтверждённый тестовый возврат. Конкуренция/rollback/намеренные блокировки остаются локальными. Браузер отдельно проходит реальную HTML форму, возврат в брони и reload.

При первом запуске 0.4 API восстановит сохранённые success 3B. Просроченные записи получат компенсации, не исторические брони. Созданные публичной приёмкой confirmed bookings сохраняются как учебная история; API отмены подтверждённой брони ещё не реализован. Прогон не удаляет рабочие данные и не меняет секреты.

Ограничения: тестовый адаптер in-process с отдельной долговечной квитанцией, не реальный банк; нет charging sessions, телеметрии, ML, управления мощностью и банковского возврата. Предоплата не является окончательной стоимостью энергии. История workspace ограничена 100 записями без пагинации; операторское управление бронированиями остаётся следующим расширением.

Источники: [PostgreSQL constraint triggers](https://www.postgresql.org/docs/17/sql-createtrigger.html), [Render deploy lifecycle](https://render.com/docs/deploys). [OpenAPI](../../backend/openapi/payments.yaml).
