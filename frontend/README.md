# Энерготранспорт — фронтенд

React + TypeScript + Vite. Интерфейс курсового проекта: поиск зарядных станций, бронирование, зарядка и управление инфраструктурой. Водитель и оператор имеют отдельные маршруты и навигацию. Операторские аккаунты выдаёт администратор; публичная регистрация создаёт только водителя.

## Запуск

```bash
npm ci
npm run dev -- --host 127.0.0.1
```

Откройте http://localhost:5173. Этот адрес соответствует ограничению HTTP Referer `localhost` в кабинете Яндекс Карт. Для проверки собранной версии: `npm run build`, затем `npm run preview`.

## Демонстрационные аккаунты

| Роль     | Почта                         | Пароль    |
| -------- | ----------------------------- | --------- |
| Водитель | driver@energotransport.test   | Demo12345 |
| Оператор | operator@energotransport.test | Demo12345 |

В режиме `mock` поля входа заполнены автоматически. Можно также зарегистрировать своего водителя. Брони, сессии, настройки и изменения станций сохраняются в браузере после перезагрузки. Без «Запомнить меня» токен хранится только в sessionStorage. Демоаккаунты доступны после первого запуска локальной базы.

Локальный режим предназначен для проверки интерфейса и защиты курсовой. Он не обеспечивает серверную безопасность: данные можно изменить в инструментах браузера. Пароли в локальной базе хешируются; реальные персональные данные вводить для демонстрации не требуется. Очистка данных сайта удаляет созданные аккаунты и историю. `localhost` и `127.0.0.1` имеют разные хранилища.

## Реализованные сценарии

- Главная, вход, регистрация водителя, восстановление доступа с одноразовой ссылкой, разделение ролей и страница неизвестного маршрута.
- Карта, поиск по адресу/названию/району, фильтры по разъёму, доступности и мощности, карточка станции.
- Бронирование на выбранной станции, проверка времени и пересечений, ожидание тестовой оплаты картой/СБП, отказ, повтор, отмена и истечение ожидания, подтверждение, история и отмена брони. Незавершённый платёж можно продолжить из списка броней. Повторное подтверждение не создаёт вторую бронь.
- Запуск зарядки по брони, расчёт энергии/заряда/стоимости, потеря и восстановление связи, устаревшая телеметрия, завершение, история и отчёт CSV. При отсутствии свежих показаний значения не растут; показания устройства никогда не экстраполируются.
- Профиль и автомобиль, уведомления, смена пароля, выход и восстановление входа.
- Операторская сводка, журнал событий, фильтры объектов, изменение мощности, сервисный режим, диагностика, просмотр/завершение сессий, лимит сети и настройки организации.
- График прогноза на сутки, выбор часа, экспорт, обновление, ошибка, повтор и предупреждение об устаревшем расчёте. Демоисточник явно обозначен; интерфейс принимает результаты модели в том же формате.
- Загрузка, ошибки и повтор запросов, пустые результаты, защита от повторных действий, адаптивные экраны и управление с клавиатуры. Рабочая область обновляется при возвращении на вкладку, изменениях в другой вкладке и каждые 30 секунд в видимой вкладке.

Тестовая оплата не списывает деньги, отчёт не является кассовым чеком. Восстановление пароля проверяется локальной одноразовой ссылкой (30 минут), без отправки писем. Доставка писем и уведомлений требует сервера; интерфейс не сообщает о несуществующей отправке. Энергия в деморежиме рассчитывается по времени и мощности, а не поступает с зарядного оборудования. Проценты загрузки объектов — исходная демонстрационная телеметрия, независимая от созданных локальных сессий.

## Подключение API

Скопируйте `.env.example` в `.env`. После изменения переменных перезапустите Vite.

```env
VITE_API_MODE=mock
VITE_API_BASE_URL=/api
VITE_YANDEX_MAPS_API_KEY=
```

Для сервера установите `VITE_API_MODE=http` и URL API. Адаптер отправляет JSON и `Authorization: Bearer <token>`, обрабатывает ошибки и прерывает зависшие запросы через 15 секунд. Сервер должен реализовать [контракт API](../docs/frontend-api-contract.md). При отдельном домене сервер должен разрешать запросы фронтенда через CORS. Режим HTTP требует реализованного сервера: клиент создаёт платёж, ожидает его статус и открывает предоставленную сервером HTTPS-страницу оплаты. Успех определяется серверным статусом, а не нажатием кнопки. Демо-кнопки исходов оплаты и телеметрии в HTTP-режиме скрыты.

## Яндекс Карты

Укажите браузерный ключ JavaScript API 3.0 в `VITE_YANDEX_MAPS_API_KEY`. Настройте разрешённые адреса приложения в кабинете Яндекса по [официальной инструкции](https://yandex.ru/maps-api/docs/js-api/common/quickstart.html). Переменные `VITE_*` попадают в браузерную сборку; здесь нельзя хранить серверные секреты.

С ключом включаются настоящая карта, маркеры, группировка близких станций, масштабирование и переход к местоположению после разрешения пользователя. Без ключа или при ошибке отображается подписанная демонстрационная схема. При ошибке доступна повторная загрузка. Проверка настоящей карты требует действующего ключа и доступа к Яндексу.

## Маршруты

| Маршрут                                         | Экран                          |
| ----------------------------------------------- | ------------------------------ |
| `/`, `/login`, `/register`                      | Публичные страницы             |
| `/driver/stations`, `/driver/stations/:id`      | Поиск и карточка               |
| `/driver/booking?station=:id`                   | Бронирование выбранной станции |
| `/forgot-password`, `/reset-password?token=...` | Восстановление доступа         |
| `/driver/checkout/:paymentId`                   | Ожидание, отказ, повтор оплаты |
| `/driver/payment/:bookingId`                    | Результат бронирования         |
| `/driver/bookings`, `/driver/sessions`          | История                        |
| `/driver/charging?session=:id`                  | Зарядка и её результат         |
| `/driver/profile`, `/driver/settings`           | Профиль и настройки            |
| `/operator`                                     | Сводка, прогноз и журнал       |
| `/operator/stations`, `/operator/power`         | Объекты и мощность             |
| `/operator/sessions`, `/operator/settings`      | Сессии и настройки             |

Для публикации содержимого `dist/` настройте на хостинге возврат `index.html` для клиентских маршрутов, чтобы прямое открытие `/driver/...` работало после обновления страницы.

Для GitHub Pages подготовлен workflow в корне проекта: `.github/workflows/pages.yml`. Он включает маршруты через `#`, поскольку Pages не поддерживает возврат `index.html` для произвольных путей. Настройка репозитория и ключа карты описана в [инструкции публикации](../docs/github-pages.md).

## Структура

- `src/pages/` — экраны по задачам.
- `src/components/` — общие элементы, карта, модальное окно и прогноз.
- `src/types/domain.ts` — типы данных и ответы сервера.
- `src/services/api.ts` — единый API для локального и серверного режима.
- `src/services/mockApi.ts` — локальный демонстрационный сервис с проверками ролей и состояний.
- `src/state/` — рабочая область, загрузка и защита маршрутов.
- `src/hooks/`, `src/utils/` — действия, время, форматирование и экспорт.
- `tests/` — проверки сценариев, доступа и HTTP-адаптера.

## Проверка

```bash
npm run lint
npm run test
npm run build
```

Для защиты используйте [сценарий демонстрации](../docs/frontend-demo.md). Следующий этап проекта — серверная авторизация и база данных, реальные платежи, телеметрия станций, доставка уведомлений и ML-модель. Это внешние части системы; их наличие не имитируется успешными сообщениями интерфейса.

Браузерная регрессия: tests/browser-smoke.mjs экспортирует runBrowserSmoke(tab, baseUrl) и runOperatorSmoke(tab, baseUrl) для запуска через CUA REPL. Скрипт принимает вкладку с входом в соответствующую роль, проверяет загрузку страниц и отсутствие горизонтального переполнения; водительский прогон также проверяет запрет входа в кабинет оператора. Сценарии действий автоматизированы отдельно в tests/app-flow.test.tsx (DOM), tests/new-flows.test.ts (локальный API).
